1. Is HTML Used?

No HTML files exist in SmartCart. It is a React Native app. However, React Native uses JSX — a syntax that looks like HTML but compiles to native mobile UI components, not web pages.

JSX in React NativeEquivalent in HTMLWhat it renders to
<View><div>Native container box
<Text><p> or <span>Native text label
<TextInput><input>Native text field
<TouchableOpacity><button>Tappable button (fades on press)
<ScrollView>Scrollable <div>Native scrollable list
<SafeAreaView>(no equivalent)Avoids phone notch/status bar
Note: The file src/global.css exists only for the web build of the app (when opened in a browser). For Android/iOS, zero CSS is used — all styling is done via JavaScript objects using StyleSheet.create(...).

This is the very first file that runs when the app launches. registerRootComponent(App) tells Expo: "This is the top-level component. Display it when the app opens." It sets up the native environment correctly on both iOS and Android so that App (from App.js) appears as the starting screen.

What each part does:

  • auth and db start as null. Every screen checks if (!auth) or if (!db) before calling Firebase, so the app always works safely.

4.3 authError() — Bilingual Error Messages (Lines 86–100)

function authError(code, lang) {
  const m = {
    'auth/invalid-email':       { en: 'That email address looks invalid.', np: 'इमेल ठेगाना मिलेन।' },
    'auth/email-already-in-use':{ en: 'This email already has an account.', np: 'यो इमेलमा खाता छ।' },
    'auth/weak-password':       { en: 'Password must be at least 6 characters.', np: 'पासवर्ड ६ अक्षरको हुनुपर्छ।' },
    'auth/wrong-password':      { en: 'Email or password is incorrect.', np: 'इमेल वा पासवर्ड मिलेन।' },
    'auth/user-not-found':      { en: 'No account found — try signing up.', np: 'खाता भेटिएन।' },
    // ...more codes
  };
  return (m[code] && m[code][lang]) || fallbackMessage;
}

Algorithm: A lookup table maps Firebase error codes to human-readable messages in both languages. The expression m[code] && m[code][lang] safely looks up the code, then the language. If neither exists, it falls back to a generic "Something went wrong" message. Called in the Login screen's catch(e) block as authError(e.code, lang).

4.4 timeAgo() — Relative Timestamps (Lines 103–112)

function timeAgo(ts, lang) {
  if (!ts) return '';
  const s = Math.max(0, (Date.now() - ts) / 1000); // elapsed seconds
  if (s < 60)  return lang === 'np' ? 'अहिले' : 'now';
  const mnt = Math.floor(s / 60);
  if (mnt < 60) return mnt + 'm';           // e.g. "5m"
  const h = Math.floor(mnt / 60);
  if (h < 24)  return h + 'h';             // e.g. "3h"
  return Math.floor(h / 24) + 'd';          // e.g. "2d"
}

Converts a Unix timestamp (milliseconds since 1970) into a short "time ago" label. Used in the Community Reports screen to show how old each report is. Date.now() gives the current time in milliseconds. Subtracting the stored timestamp gives elapsed time, which is then bucketed into seconds, minutes, hours, or days.

4.9 Conversational Helper — getReply() (Lines 513–574)

The chatbot logic follows a priority chain — each step is checked in order, and the first match wins:

Input text │ Step 1 → Is it a greeting? (hi, hello, namaste, नमस्ते...) │ → Return: "Hello! How can I help you shop safely?" │ Step 2 → Is it a thank-you? (thanks, dhanyabad, धन्यवाद...) │ → Return: "You're welcome! Stay safe." │ Step 3 → Is it asking for help/guide? │ → Return: list of what the bot can do │ Step 4 → Does it look like a scam to check? │ (URL, phone number, or scam keywords present) │ → Run detectRisk() → return verdict + reasons + actions │ Step 5 → Does it match a FAQ topic? │ (loop through 9 FAQ entries, check keywords) │ → Return: the FAQ answer for that topic │ Step 6 → Fallback → Return: generic "here's what I can do" message

looksCheckable() — Decides if Input Should Be Scam-Checked

function looksCheckable(t) {
  return (
    /https?:\/\//.test(t)                      || // has a URL (http:// or https://)
    /\b(bit\.ly|tinyurl|t\.me|wa\.me)\b/.test(t) || // shortened link
    /\b9[678]\d{8}\b/.test(t)                  || // Nepal phone number
    /(otp|advance|prize|esewa|khalti|...)/i.test(t) // scam keywords
  );
}

4.11 Screen Components

Welcome Screen (Lines 620–652)

Shown once on first launch before the user logs in. Displays the app name, tagline, and a short description. Offers two buttons to choose language (Nepali / English). A "Get started" button calls onDone() which sets seenWelcome = true → navigates to Login.

Login Screen (Lines 654–734)

  • Manages two modes with one mode state variable: 'login' or 'signup'
  • Sign-up mode shows an extra Name field
  • On submit: calls Firebase createUserWithEmailAndPassword or signInWithEmailAndPassword
  • Errors caught in catch(e) are passed through authError(e.code, lang) for friendly bilingual messages
  • busy state disables the button and shows a spinner while Firebase responds
  • "Continue as guest" bypasses Firebase entirely and sets guest = true
  • KeyboardAvoidingView with behavior="padding" on iOS prevents the keyboard from hiding inputs

Home Screen (Lines 744–777)

  • Displays a greeting: "Hello, [name] 👋"
  • Renders a 2-column grid of 5 feature cards (Scam Check, Helper, Learn, Report, Contact)
  • Each card's onPress calls go(key) → setTab(key) to navigate to that screen
  • A daily safety tip card at the bottom (static text from translations)

CheckScreen (Lines 779–835)

  • User types or pastes text into a large multiline TextInput
  • "Check" button calls detectRisk(input) and stores result in result state
  • "Clear" button resets both input and result to empty
  • When result is not null, renders:
    • VerdictCard — colored banner (green / orange / red) with emoji and label
    • Reasons list — bullet points explaining why the text is risky
    • Actions list — what to do next (choose COD, don't share OTP, report, etc.)

ChatScreen (Lines 837–895)

  • Maintains a msgs array: each entry is { from: 'user'|'bot', text, level }
  • send() function:
    1. Takes the input text
    2. Calls getReply(text, lang) to get the bot's response
    3. Appends both the user message and bot reply to msgs
    4. Clears the input field
    5. Waits 80ms then auto-scrolls to the bottom using scrollRef.current.scrollToEnd()
  • Bot messages with a scam verdict get a colored left border (red/orange/green)
  • User messages are shown on the right (blue background), bot messages on the left (white)

LearnScreen (Lines 897–912)

Read-only educational screen. Maps over the LESSONS array and renders each as a card with an emoji icon, bold title, and descriptive body text. No interactivity.

ReportScreen (Lines 914–1016)

This screen uses Firebase Realtime Database. Key logic:

// Live subscription — runs when screen mounts
useEffect(() => {
  if (!db) { setLive([]); return; }
  const q = query(dbRef(db, 'reports'), limitToLast(50)); // last 50 reports
  const unsub = onValue(q, (snap) => {
    const val = snap.val() || {};
    const arr = Object.entries(val)           // convert object to array
      .map(([id, v]) => ({ id, ...v }))
      .sort((a, b) => (b.ts || 0) - (a.ts || 0)); // newest first
    setLive(arr);
  }, () => setLive([])); // on error, show empty
  return () => unsub(); // unsubscribe when screen unmounts
}, []);
  • onValue is a real-time listener — whenever someone submits a new report anywhere, all connected users' screens update automatically within seconds
  • The Firebase data is an object keyed by auto-generated push IDs. Object.entries() converts it to an array, sorted by timestamp (newest first)
  • If Firebase is unavailable, fallback sample reports are shown
  • Submit form: push(dbRef(db, 'reports'), {...}) adds a new entry with seller name, description, risk level, reporter identity, and current timestamp

ContactScreen (Lines 1018–1070)

  • 4 contact info rows: email, phone, address, office hours
  • Email row: Linking.openURL('mailto:support@smartcart.np') opens the device's email app
  • Phone row: Linking.openURL('tel:+97714000000') opens the device's phone dialer
  • Message form shows a "Thank you" message on submit (UI only — no real backend submission)

DecisionWhy It Was Made
Single App.js file (1343 lines)Can be pasted directly into Expo Snack (snack.expo.dev) and run instantly without any setup. Great for demos and learning.
No router libraryA simple tab state variable is enough for 6 screens. Saves one dependency and keeps navigation trivially understandable.
No icon libraryIcons drawn from plain <View> elements = zero bundle size overhead. No additional npm package to install or update.
Rule-based scam detectionNo machine learning or external API needed. Works completely offline. Fast (runs instantly). Easy to understand and explain to users. Easy to add new rules.
Firebase fallback to local modeThe app still fully works (scam check, chat, learn, contact) even if Firebase is unavailable, misconfigured, or the user has no internet.
Bilingual STR objectAll UI text in one place. Switching language is a single state change. Easy to add a third language (e.g., Maithili) by adding a new key.
useMemo for translationsThe translation lookup STR[lang] only re-runs when lang changes — not on every state update or re-render.
Guest modeUsers can use all features without creating an account. Only community reports require Firebase (and even those fall back to sample data).
